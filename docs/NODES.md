# Система нод («Чёрный ящик»): концепция и технический план

## 1. Исходный фрагмент брифа (автор, дословно)

> **«ЧЕРНЫЙ ЯЩИК» — КОНЦЕПТУАЛЬНЫЙ И ТЕХНИЧЕСКИЙ МАНИФЕСТ САЙТА**
>
> **1. Концептуальная архитектура и позиционирование**
> Сайт полностью отказывается от устаревшей парадигмы портфолио с унылыми сетками кейсов. Это интерактивный
> арт-объект и пульт управления смыслами, отражающий суть работы арт-директора и архитектора цифровых систем.
> Пользователь не пассивный зритель, а соавтор, который соединяет узлы пайплайна, чтобы извлечь нужную грань
> профессионального профиля.
>
> **Базовые константы (Ноды)** — на холсте представлены 4 фундаментальные ноды:
> 1. `[ Я ]` — Субъект / Личность / Арт-директор.
> 2. `[ Смысл ]` — Концепция / Идея / Стратегия.
> 3. `[ Код ]` — Пайплайн / ИИ / Технологии.
> 4. `[ Форма ]` — Моушн / Пространство / Эстетика.
>
> **Математика состояний (Карта комбинаций)** — система обрабатывает все 11 математических переплетений,
> разворачивая их в 6 ключевых разделов и глубокие смысловые манифесты:
> - [ Я ] → Обо мне (Позиционирование и оптика).
> - [ Смысл ] → Манифест метода (Первичность концепта).
> - [ Код ] → Технологический стек (Инструментальная база).
> - [ Форма ] → Эстетический срез (Пространственные эксперименты).
> - [ Я ] + [ Смысл ] → Подход и принципы (Архитектура мышления).
> - [ Смысл ] + [ Форма ] → Концепции и визуальные коммуникации (Синтез идеи и визуализации).
> - [ Код ] + [ Форма ] → Шоурил (Бесшовный поток моушн-мощи).
> - [ Я ] + [ Код ] → Партнеры и клиенты (Вес в индустрии и опыт).
> - [ Я ] + [ Форма ] → Авторский почерк (Тактильность и эстетика).
> - [ Смысл ] + [ Код ] → ИИ и Системный дизайн (Алгоритмы как расширение мысли).
> - [ Я ] + [ Смысл ] + [ Код ] + [ Форма ] → Контакты / Сингулярность (Полный доступ к системе связи).
>
> **2. UX/UI и паттерны взаимодействия**
> - Швейцарский минимализм: Абсолютный глубокий черный мат на фоне, пронзительная тишина, тончайшая векторная
>   сетка, моноширинная типографика и детекционный вайб компьютерного зрения.
> - Ненавязчивое обучение (Onboarding): При загрузке сайта система делает мягкий авто-тизер (невидимая «рука»
>   соединяет ноду `[ Я ]` с ядром), мгновенно показывая пользователю механику без удушающих туториалов.
> - Кинематографический димминг и квантовые нити: При зажатии любой ноды всё на холсте (кроме центра и свободных
>   нод) деликатно уходит в теневой монохром, а точно из центра зажатой точки веером распускаются тончайшие
>   нити-паутинки, показывающие потенциал возможных соединений.
> - Дуал-режим (Планы «А» и «Б»): Для вовлеченных пользователей работает интерактивный пайплайн; для тех, кто
>   пришел по делу, в верхнем углу предусмотрен лаконичный гамбургер-меню с прямым доступом ко всем 6 состояниям.
>
> **3. Мобильная адаптация и тактильный отклик (Haptics)**
> - Дуализм кроссплатформенности: На десктопе сайт разворачивается как полноценный интерактивный арт-объект
>   с физикой мыши; на мобильных устройствах интерфейс адаптируется под компактный формат, где главным
>   инструментом навигации становится гамбургер-меню или упрощенный тач-интерфейс.
> - Нативная вибрация (Vibration API): На смартфонах задействован тактильный отклик. Каждое зажатие ноды,
>   соединение нитью или системный глитч сопровождаются короткими плотными микро-импульсами, создающими ощущение
>   управления физическим механическим пультом.

## 2. Переосмысление под текущую концепцию

### Что изменилось с брифа
Центр страницы теперь не абстрактное «ядро», а **мыслеформа** — живая фигура из частиц (пион, медуза, ещё ~7
процедурных фигур), которая перетекает в следующую через дымный вихрь. Фон — две «весики» кругов с крестиками
и звёздочками, галактика и дымка. Значит, пульт управления смыслами получает естественное тело:

- **Ядро = мыслеформа.** Соединяя ноды, пользователь не «открывает раздел», а **заставляет мысль сменить
  форму**: текущая фигура распадается в вихрь и собирается в фигуру-образ выбранного состояния. Морфинг —
  это и есть переход между разделами (бесшовный, без перезагрузок и «страниц»).
- **Ноды стоят на геометрии фона.** Четыре крестика малой весики — готовые места для четырёх нод:
  верх-лево `[ Я ]`, верх-право `[ Смысл ]`, низ-лево `[ Код ]`, низ-право `[ Форма ]` (раскладку можно
  менять). Крестик и есть «гнездо» ноды: подпись в квадратных скобках, моноширинный шрифт, как на эскизе.
  Четыре звёздочки большой весики — места для второстепенного (служебные ноды, гамбургер, контакты) или
  просто «звёзды» композиции.
- **Нити = частицы.** Соединение ноды с ядром — тонкая нить из частиц от крестика к фигуре (та же эстетика
  точек, что у фигур). При зажатии ноды нити веером расходятся к ядру и к другим нодам, всё остальное уходит
  в тень (димминг фона и фигуры).
- **Окно ответа.** Результат соединения — окно поверх композиции (на эскизе — «[ ФОРМА ]» в центре):
  появляется из вихря морфинга (например, рамка «детектирует» фигуру, как компьютерное зрение), содержит
  манифест/раздел. Малые окна у нод (на эскизе «[ Я ]», «[ СМЫСЛ ]», «[ ФОРМА ]») — превью/статус ноды.

### Карта состояний: 15 комбинаций вместо 11
Из 4 нод получается 15 непустых наборов: 4 одиночных + 6 пар + 4 тройки + 1 полный. В брифе тройки не
расписаны — предлагаю: **тройка = раздел пары внутри неё с наибольшим «весом» + оттенок третьей ноды**
(или: тройки — «переходные» состояния без своего окна, фигура-гибрид). Решает автор.

Каждому состоянию — **своя мыслеформа** (фигура) и свой характер морфинга:

| Состояние | Раздел | Мыслеформа (предложение) |
|---|---|---|
| — (ничего не соединено) | Заставка | пион (текущая) |
| [ Я ] | Обо мне | медуза? (живое, дышащее, «я») |
| [ Смысл ] | Манифест метода | кристалл / семя |
| [ Код ] | Технологический стек | решётка / сеть узлов |
| [ Форма ] | Эстетический срез | лента Мёбиуса / волна |
| [ Я ] + [ Смысл ] | Подход и принципы | … |
| [ Смысл ] + [ Форма ] | Концепции и визуальные коммуникации | … |
| [ Код ] + [ Форма ] | Шоурил | … (фигура может «раскрываться» в видео) |
| [ Я ] + [ Код ] | Партнёры и клиенты | … |
| [ Я ] + [ Форма ] | Авторский почерк | … |
| [ Смысл ] + [ Код ] | ИИ и системный дизайн | … |
| все четыре | Контакты / Сингулярность | сфера / чёрная дыра (галактика стягивается в центр) |

Около 9 фигур в плане — значит, часть состояний может делить фигуру (с разным цветом/поведением) — решает автор.

### Поведение (переосмысленный UX)
- **Онбординг.** При загрузке — пион; через пару секунд невидимая «рука» тянет нить от `[ Я ]` к ядру,
  пион перетекает в фигуру «Я», появляется окно «Обо мне». Одного раза достаточно, чтобы понять механику.
- **Соединение.** Зажал ноду → димминг + нити-веер; протянул к ядру (или к другой ноде, если уже есть
  соединение) → отпустил → нить закрепилась, запускается морфинг в фигуру нового состояния, окно ответа.
  Разрыв нити — щелчок по ней / по ноде ещё раз.
- **Быстрые смены.** Морфинг сейчас ≈3.5 с; если пользователь меняет набор во время морфинга —
  очередь «последний побеждает» (уже есть в orchestrator.morphTo). Для отзывчивости можно укоротить морфинг
  при интерактиве (ползунки «распад/сборка») или перехватывать вихрь в середине (перепланировать посадку).
- **План «Б».** Гамбургер слева вверху (так записано в плане CLAUDE.md) — список состояний; выбор = тот же
  морфинг + окно, нити рисуются сами (видно, какие ноды соединились).
- **Мобильные.** Ноды — на тех же крестиках (весика масштабируется), тап по ноде = соединить с ядром,
  второй тап = разорвать; тянуть нити не обязательно. Гамбургер — основной путь.
- **Haptics.** `navigator.vibrate` работает в Android Chrome; **в iOS Safari Vibration API нет** — на iPhone
  тактильного отклика из веба не будет (только визуальный «щелчок»). Учесть при обещаниях.

## 3. Технический план (в нашем коде)

1. **Геометрия нод из HUD.** Вынести расчёт весики (R, R2, точки пересечений) из `stage.js drawHud` в общую
   функцию `DP.hudGeometry(w, h)`; ноды и нити берут координаты оттуда → всё масштабируется вместе с кругами.
2. **Слой нод — DOM** (`js/ui/nodes.js`): кнопки с подписями `[ Я ]` и т. п. поверх canvas, позиционируются по
   `DP.hudGeometry`; доступность (фокус, клавиатура, aria), pointer events (зажатие, перетаскивание).
3. **Нити — WebGL-частицы** (`js/ui/threads.js`): кривая Безье от ноды к ядру (экранные координаты →
   плоскость сцены), по ней бегут точки (та же текстура частиц); веер — несколько кривых с шумом; появление/
   исчезновение по кривым ease.
4. **Димминг** — uniform `uDim` во всех материалах фигур и фона (монохром + яркость), плюс CSS-затемнение HUD.
5. **Машина состояний** (`js/core/states.js`): набор нод — битовая маска 0..15 → состояние
   `{ figure, window, morph: {…параметры} }` (таблица в одном месте); `setState(mask)` → `DP.morphTo(figure)`
   + показ окна; адрес `#state=я+смысл` для глубоких ссылок и кнопки «назад».
6. **Окна ответа** (`js/ui/windows.js`): HTML-окна (как на эскизе: заголовок в скобках, моноширинный шрифт,
   тонкая рамка); контент — из `content/*.md|json`; появление синхронизировать с фазами морфинга
   (`orchestrator` события `morphstart/morphprogress/morphend`).
7. **Фигуры.** Каждая новая мыслеформа — файл в `js/figures/` (как пион и медуза); морфинг «диск» уже умеет любые
   пары; заблаговременная подготовка (planAhead) — сейчас для «следующей по кругу» фигуры; для нод — готовить
   переход в фигуры соседних состояний (1–2 самых вероятных) или считать при нажатии (~70 мс).
8. **Онбординг** — сценарий на тех же вызовах (`setState`), отключается навсегда после первого взаимодействия
   (localStorage).
9. **Гамбургер** — `js/ui/menu.js`, список из таблицы состояний.
10. **Haptics** — обёртка `DP.haptic(pattern)` с проверкой поддержки; вызовы в местах зажатия/соединения/глитча.

Порядок работ (предложение): геометрия → ноды (DOM) → машина состояний с двумя фигурами (пион/медуза) →
нити → димминг → окна → гамбургер → онбординг → остальные фигуры → haptics.
