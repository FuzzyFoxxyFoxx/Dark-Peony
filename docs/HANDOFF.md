## Технические находки (не наступать снова)
- **Chrome на Mac (ANGLE/Metal): `gl_PointSize = 0.0` НЕ прячет точку.** Прятать выносом за экран:
  `gl_Position = vec4(2.0, 2.0, 2.0, 1.0); gl_PointSize = 0.0;` (после `dpMorphFinish()`). В серафиме исправлено;
  в других фигурах/модулях при «не прячется» — проверить то же.
- Время `DP.shared.uTime` общее с загрузки страницы; движения, которые должны начинаться «с момента появления»
  фигуры (орбиты светила, кольца серафима), «пристёгиваются» в `instance.update` (разрыв времени > 0.25 с).
- В орбите спутника (светило) сдвиг считается от постоянной фазы планеты в покое (`uParentPhase0`) — не от
  «пристёгнутой».
- Точки раскладки (`layout.parts[].rest`) — положения в покое, без анимации шейдера.

### ГЛАЗ (центральный, `?parts=eye`) — готов, принят автором («всё получается замечательно»)
Сделан на базе референса автора (`docs/refs/seraph/eye-*.{webp,png}`; лист 0°/30°/60°/90°). Устройство:
- Кожа — ОДНА поверхность z(x,y): вертикальный профиль PROF_C (снят ПРОГРАММНО с белого контура автора, потом сглажен гауссом SMOOTH 0.13 —
  иначе излом кривой давал лишние полоски от френеля/света) + гладкий PROF_S; горизонтальный переход между ними по x (`creaseHalf`, `creaseFlat`),
  парабола вида сверху (супер-гауссиана `paraA/paraW/paraP`), борозда — отдельный гаусс (`groove*`), разрез-«лимончик» (верх — дуга, низ — половина
  лимона, острые уголки), лоскут уходит в прозрачность неровным контуром (`fade*`), край разреза уходит в ноль за 2–3 частицы (`edgeFade`).
- Яблоко — сфера под кожей (рядки-параллели, середина почти невидима), роговица — купол-«нашлёпка» (`cornea`), веки облегают её.
  Радужка — волокна от зрачка. Взгляд = поворот яблока; вниз ограничен (`downK`).
- Веки ПРИВЯЗАНЫ К ПОЛОЖЕНИЮ КОЖИ В ПОКОЕ и едут с ней (eSkin/eSurf2): при моргании двигаются оба века между кромкой и бороздой/скулой; борозда и
  лоб/скула неподвижны. Растяжение кожи при смыкании компенсируется размером и яркостью точек (eStretch). Веки следят за взглядом (`lidFollow`):
  вверх — верхнее поднимается, вниз — верхнее прикрывается целиком (без изгиба), изгибается нижнее; при взгляде вбок изгиб — колокол по x над
  роговицей (`lidLocal`, `lidW`, `lidSide` 1 / −1 зеркально; автору нравится +1 вверх).
- Свет: снизу-справа-спереди (тень складки над глазом), светотень по нормали, ореол/френель — по сглаженному градиенту.
- ЗНАЧЕНИЯ ПОЛЗУНКОВ АВТОРА зашиты в умолчания (блок `DP.config.seraphEye` в начале seraph.js; список — в `CLAUDE.md` «БАЗА ГЛАЗА»).
- Метод проверки, который работал: сравнение «референс слева / мой кадр справа» по 4 ракурсам + срезы профиля (`DP.eyeSurfZ`: вертикальные срезы z(y) при разных x и
  горизонтальные z(x) при разных y — так нашли ступеньку на y=0) + график кривизны (максимум |z''| по y; нормально ≈3–5, пик у уголков был 16) + плотная раскадровка моргания (`DP.eyeOpen`).

### ЛЕПЕСТКИ (`?parts=cross`) — в работе, сейчас только форма
Решения автора (2026-09-30): лепестки доводим ПО ОДНОМУ, потом по образцу остальные. Сначала плоские (без синусоид/полей). ПРАВИЛА:
1. Ось лепестка — ПРЯМАЯ (основание и кончик на одной линии); изгиб — только от будущих деформаций. Ширина вокруг оси НЕсимметрична (две таблицы, слева/справа).
2. Рандомайз ЗАЛОЖЕН НА УРОВНЕ КОНСТРУИРОВАНИЯ (постоянный, не анимируется): у каждого лепестка свой `seed` (`petalSeed(idx)`), свой плавный микс двух базовых форм `mix`,
   своя ширина ±12% по каждой стороне отдельно, длина ±6%. Левые НЕ зеркальны правым, два лепестка одного типа различаются.
3. Форма обреза (силуэт) — постоянная; волнистость краёв в плоскости — переменная, ею будем играть (шаг 2).
4. Ножки короче, утолщение раньше (параметр `ex` в PETAL_TYPES: ширина берётся из таблицы в точке u^ex); никаких «лопухов» (слишком широких).
Структура (PETALS — 6 пар по 2 стороны = 12; индекс i = 2·пара + (0 левый, 1 правый)); типы — в `PETAL_TYPES` (семейство из двух базовых форм A–F из выкройки ириса автора):
| пара | угол, рад | тип | смысл |
|---|---|---|---|
| 0 | 0.30 | C/E | верхний высокий (линза/ланцет) |
| 1 | 0.90 | A3/A2 | диагональный широкий — ВТОРОЙ по крупности (лепесток 3 — «лидер»: на нём доводим края) |
| 2 | 1.38 | E/C | экваториальный узкий длинный (выше горизонтали) |
| 3 | 1.80 | E/D | экваториальный узкий длинный (ниже горизонтали) |
| 4 | 2.38 | D/B | нижнее крыло — САМЫЙ БОЛЬШОЙ (L 3.05) |
| 5 | 2.95 | F/E | лента вниз (длинная узкая) |
CROSS = [2, 3, 8, 9] (диагональные верхние и нижние крылья). Идея автора: «крестом» доводим форму этих четырёх, потом добавляем остальные лепестки МЕЖДУ ними.
Референсы: `docs/refs/seraph/petals-*` (картинка автора «сгенерирована с наброска», выкройка ириса, фото ириса, скриншот креста, ретушированный автором ликвифаем —
`petals-cross-retouched-by-author.webp`) и `sketch-seraphimus.png` (исходный набросок). По ретуши я измерил углы/длины на глаз (2 числа на лепесток); точный контур не снимал.

### Что делать дальше (порядок)
1. Поправить углы осей (после выпрямления оси кончики смотрят иначе, чем на ретуши автора) — лучше ПО КОНТУРУ: попросить у автора ретушь без подписей и снять силуэт по пикселям
   (как с глазом: крайние точки/контур → масштаб → таблица). Состав на ретуши: 4 лепестка; пропорции верхних/нижних ≈ 0.89.
2. Край-«рюши» (шаг 2, как у медузы): два радиуса — постоянный «обрез» + синусоида с рюшками переменной длины и высоты волны (см. ribbonPoint/dpBezWave/dpRibbonWave
   в `jellyfish.js`, одна формула для CPU и GLSL). Вопрос автора «не станут ли лепестки узкими полосками»: следить (pwk/wk), проверять на нескольких значениях.
3. Добавить остальные лепестки между крестом; затем z-форма (кончик к зрителю, чаша краёв), взмах, прожилки, светимость («рентген», как орхидея), центр — глаз на месте, усики, кольца.
4. Совместить глаз и лепестки (глаза на лепестках привязаны к точке лепестка и «дышат» с крылом; `EYES` в начале файла ссылаются на индексы лепестков — при смене набора проверить), вес фигуры сравнить с пионом/медузой, iPhone.
