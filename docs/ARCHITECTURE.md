# Dark Peony — архитектура фоновой анимации

## Файлы

```
index.html               оболочка: HUD, кнопки, подключение скриптов
css/main.css             стили (safe-area, тач, Safari-префиксы)
vendor/three.r134.min.js three.js r134 (MIT) — локальная копия, без CDN
js/core/dp.js            пространство имён DP, конфиг (в т.ч. тайминги морфинга), качество, утилиты
js/core/morph.js         механизм морфинга: GLSL-блоки + планировщик пар частиц
js/core/stage.js         рендерер, камера, HUD, фон, ресайз, адаптивное качество, потеря контекста
js/core/orchestrator.js  реестр фигур + оркестратор (show / morphTo / события)
js/figures/peony.js      фигура «пион»
js/main.js               запуск, цикл кадров, кнопки и клавиши
archive/                 эталонная версия цветка (005_crossplatform) для сравнения
```

Скрипты обычные (не ES-модули) — сайт работает и на GitHub Pages, и при открытии `index.html` двойным кликом.

## Управление

| Действие | Клавиша / кнопка | Из кода |
|---|---|---|
| Морфинг | `Space` / `N`, кнопка MORPH | `DP.morphTo('peony')` |
| Точки / поверхность | `M` (в любой раскладке), кнопка | `DP.orchestrator.setPointsMode(bool)` |

События оркестратора (для будущих нод и меню):
`DP.orchestrator.on('morphstart' | 'morphprogress' | 'morphend' | 'mode' | 'show', fn)`.
Если морфинг уже идёт, новый запрос встаёт в очередь (последний побеждает). `morphTo` возвращает Promise.

## Параметры URL (для тестов)

- `?q=low|medium|high` — уровень качества (по умолчанию `high`; `medium`/`low` выбираются автоматически
  только на очень слабых устройствах, где браузер сообщает ≤ 3 ГБ памяти или ≤ 4 ядра).
- `?adaptive=0` — отключить автоматическое понижение pixelRatio при низком FPS.
- `?webgl1` — принудительно WebGL1 (проверка совместимости).
- `?manual` — время стоит, его двигает `DP.debug.step(секунды)` (для автотестов и скриншотов).
- `?figure=имя` — стартовая фигура.

## Как устроен морфинг

1. **Порядок распада.** Фигура записывает каждой точке атрибут `aOrder ∈ [0..1]`:
   `0` — отрывается первой, `1` — последней. У пиона это расстояние от основания цветка
   (кончики щупалец и лепестков → к низу и центру) + шумовая неровность фронта + «песчинки».
2. **Пары.** `DP.morph.plan(A, B)` сортирует точки: k-я уходящая из A становится k-й
   прилетающей в B. По умолчанию B собирается так же, как A распадалась: от краёв к центру и низу
   (`config.morph.assemble`).
   Если точек в фигурах разное количество — лишние гаснут или рождаются внутри вихря.
3. **Полёт.** Каждая точка: дрожь и подсветка перед отрывом → облёт оси Y
   (`config.morph.turns` оборотов, по умолчанию 360° ± разница азимутов старта и финиша) → посадка.
   Середина пути — непрерывное отображение цветка в кольцо: соседи на цветке остаются соседями
   в вихре (`cloudMix` подмешивает случайную точку), поэтому лепесток на глазах вытягивается в ленту,
   а не тает в пыль. Вес пути — с плато в середине (`swirlHold`): частица долго целиком в вихре.
   **Сейчас (по референсам с распадом черепа):** кольца нет (`ringMode: false`) — каждая частица остаётся
   на своём уровне и радиусе, облетает ось Y и садится на новое место. Сильное плавное поле
   (`flowAmp/flowFreq` + складки `flowDetail*`) берётся в исходной точке частицы, повёрнутой вокруг оси,
   поэтому соседи сдвигаются одинаково: лепесток срывается цельной вуалью, изгибается и складывается.
   Случайные разбросы выключены (`lift: 0`, `travelJitter: 0.4`).
   Распад на частицы даёт случайный разброс времени у каждой частицы (`ORDER_JITTER` у пиона,
   `travelJitter`). Дрожь перед отрывом (`shiver`) и вспышка (`leaveGlow`) выключены — они давали
   мерцание при разборе; `swirlLook` (0..1) — насколько частица в полёте меняет свой вид.
   **Темп участков** (`speedIn`, `speedMid`, `speedOut`): путь частицы делится на уход (до выхода на плато
   вихря), вихрь и посадку; каждый проходится со своей скоростью, стыки сшиты кривыми Эрмита (без рывков).
   Фронт распада ускоряется в `speedIn` раз; поверхности MESH прогорают/проявляются по тем же срокам.
   **Морская волна** (`wave*`, основной режим): радиус полёта не меняется, частица поднимается и опускается
   по синусоиде; фаза = угол на пути × `waveCount` + радиус × `waveRadial` − время × `waveSpeed`
   (+ вторая гармоника), включается вместе с поворотом (как поле). Соседи качаются вместе.
   **Поле среды** (`flow*`, сейчас выключено `flowAmp: 0`): частицы толкает поле водоворотов (∇n1 × ∇n2 — только завихрения, без «ям»),
   смещение — сумма толчков вдоль уже пройденного идеального пути за `flowMemory` секунд (`flowSteps`
   отсчётов: high 5, medium 4, low 3). Поле вращается вместе с вихрем медленнее частиц (`fieldSpin`)
   и меняется во времени (`flowSpeed`). Частицы с разной историей расходятся — сгущения и пустоты.
   Сила поля привязана к прогрессу поворота (0 на месте → 1 в середине вихря): поле включается после
   `fieldDelay` и так же раньше гаснет перед посадкой; переход с позы цветка на траекторию — за
   `poseBlend` поворота. Так нет бокового рывка на старте: сначала движение по кругу, потом «среда».
   **Нити** (`threadCell`, по референсу распада человека в частицы): середина пути квантуется
   по ячейкам сечения кольца — все частицы ячейки идут по одной линии (как линии тока), каждая со своего
   места и в своё время, поэтому растягиваются вдоль неё цепочкой. Форма нити — плавная волна
   (`flowAmp/flowFreq`) + свои у каждой нити завитки (`flowDetail*`); поле берётся в точке идеального
   пути, одинаковой для всей нити. Стягивание в жгуты, перекрут и хвосты-лидеры давали хаос —
   выключены нулями в конфиге (код оставлен).
   **Перекрут ленты** (`twist*`): сечение кольца поворачивается вокруг своей средней линии по ходу
   вращения и во времени — плоская лента складывается в жгут, частицы идут по спиралям.
   Поле течения — две волны: крупная (`flowAmp/flowFreq`: подъёмы, спуски, уходы внутрь/наружу)
   и мелкая (`flowDetail*`: неоднородность среды). Яркость и цвет вихря частица набирает только
   глубоко в вихре (`swirlBlend`, `swirlTint`) — дальние тусклые лепестки не «проявляются сверху»;
   подсветка перед отрывом ослаблена (`leaveGlow`).
   **Лидеры и хвосты** (`trail*`): соседние точки объединяются в хвосты; брат №k летит по расписанию
   лидера с задержкой k·`trailLag` и повторяет плавную часть его пути (поток, покачивание) с этой
   задержкой, а к жгутам прилипает по текущему времени — хвост ложится вдоль жгута. Без GPGPU:
   всё вычисляется в вершинном шейдере из данных, записанных планировщиком.
   В середине пути точки собираются в кольцо вокруг оси. Сечение кольца — «крыло» (`ring*`):
   толстое скруглённое ближе к оси и тонкий острый хвост далеко за радиус цветка — редкие частицы
   за основным бубликом. Поле течения на simplex-шуме изгибает кольцо, а «стягивание» (`clump*`)
   в два шага Ньютона сажает частицы на нулевую поверхность одного поля шума и, двигаясь вдоль неё,
   на линию пересечения со вторым полем — получаются тонкие жгуты. Поля считаются в реальной позиции
   частицы (иначе жгуты расползаются в муть) и живут в потоке: вращаются вместе с вихрем
   (`fieldSpin`), у оси быстрее, чем снаружи, поэтому наматываются в спиральные рукава
   (`fieldShear`); поверхности дрейфуют в разные стороны, и жгуты ползут, рвутся и пересоединяются
   (`clumpSpeed`). Пыль вне структур притушена (`dustAlpha`). В режиме Add плотные места светятся за счёт скучивания,
   часть частиц остаётся пылью вокруг. Уход и посадка перекрываются во времени.
4. **Эстафета.** В середине пути (s = 0.5) положение и цвет точки зависят только от общих
   данных пары, и точка A сменяется точкой B. Поэтому у каждой фигуры могут быть свои шейдеры,
   своя анимация и свой внешний вид.
5. **MESH-режим.** Поверхность прогорает по тому же фронту и превращается в частицы,
   у новой фигуры — проявляется после посадки частиц.

Все тайминги и форма вихря — в `DP.config.morph` (`js/core/dp.js`).

## Как добавить новую фигуру

Создать `js/figures/<name>.js`, подключить в `index.html` после `peony.js`:

```js
(function (DP) {
    DP.figures.register({
        name: 'lotus',
        createInstance(ctx) {
            // 1) геометрия (лучше кэшировать по ctx.quality — экземпляров бывает два одновременно)
            //    у каждой геометрии точек — атрибут aOrder (Float32, 0..1)
            // 2) материалы: uniforms = Object.assign({...свои}, DP.morph.uniformsFor(ctx.uniforms))
            // 3) layout = DP.morph.createLayout([{ geometry, rest }])
            //    rest — Float32Array xyz точек В ПОКОЕ в пространстве сцены (root.matrix * part.matrix * p)
            return { root, pointsRoot, meshRoot, layout, dispose() { /* материалы */ } };
        }
    });
})(window.DP);
```

Вершинный шейдер точек:

```glsl
${DP.morph.glsl.pointsVertex}
void main() {
    vec3 dpRest = position;           // точка в покое (локальные координаты объекта)
    vec3 pos = position + анимация;   // текущая позиция
    vec4 mv = viewMatrix * dpMorph(dpRest, pos);   // вместо modelViewMatrix * vec4(pos, 1.0)
    gl_Position = projectionMatrix * mv;
    gl_PointSize = ...;
    dpMorphFinish();                  // последней строкой
}
```

Фрагментный шейдер точек: `${DP.morph.glsl.pointsFragment}` и
`gl_FragColor = dpMorphColor(цвет, альфа, tex.a);`

Поверхности: `${DP.morph.glsl.meshVertex}` + `vDpOrder = aOrder;` в вершинном,
`${DP.morph.glsl.meshFragment}` + `float glow = dpMeshGlow();` в фрагментном.

Важно: статичные смещения (изгибы, которые не зависят от времени) либо запечь в позиции на CPU,
либо учесть в `dpRest` — иначе точка при старте морфинга «прыгнет».

## Кроссплатформенность — что учтено

- three.js лежит в репозитории (CDN может быть недоступен или заблокирован).
- Размер точек учитывает `devicePixelRatio`: эталон — DPR 2 (MacBook, iPhone). На обычных мониторах
  с DPR 1 точки теперь того же видимого размера, а не вдвое крупнее (`config.pointSizeRefPixelRatio`).
- Логика размера точек на вертикальных экранах (фиксация по высоте) сохранена как была.
- Свой таймер с ограничением шага: после сворачивания вкладки нет скачка анимации и морфинга.
- Адаптивное качество: при FPS < 40 pixelRatio понижается ступенями до 1.
- Уровни качества `medium`/`low` с компенсацией плотности (размер и яркость точек).
- Потеря WebGL-контекста (частая на мобильных в фоне) обрабатывается, контекст восстанавливается.
- Нет WebGL → понятное сообщение вместо чёрного экрана.
- `position: fixed` + `inset` для холстов, `viewport-fit=cover` и safe-area для кнопок (вырез iPhone),
  `touch-action`, `overscroll-behavior` (без резинки и зума), `-webkit-backdrop-filter` для Safari,
  hover только на устройствах с мышью, клавиши по `e.code` (любая раскладка).
- `frustumCulled = false` у частей фигур — вихрь выходит за исходные границы геометрии.
