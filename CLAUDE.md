# Правила работы с проектом Dark Peony

Сайт публикуется на GitHub Pages из ветки `main`:
https://fuzzyfoxxyfoxx.github.io/Dark-Peony/
Архитектура и устройство морфинга описаны в `docs/ARCHITECTURE.md`.

## 1. Работаем прямо в main

После каждой правки делать коммит и пуш в `main` (`git push origin HEAD:main`),
чтобы изменения сразу появлялись на GitHub Pages. Перед пушем подтянуть `origin/main`.

## 2. Проверка визуала и FPS

- **В облаке (без GPU)** скриншоты рендера НЕ делать: это очень медленно. Проверять только,
  что в консоли нет ошибок и шейдеры компилируются (headless Chromium, `?q=low`, маленькое окно,
  `?manual` + `DP.debug.step(сек)`; проверять WebGL1 `?webgl1`, режим MESH и старт морфинга).
- **Локально (VS Code + Chrome с GPU)** можно и нужно смотреть самому: MCP-сервер `chrome-devtools`
  подключён в `.mcp.json`. Открывать сайт (локальный `index.html` или GitHub Pages) с `?debug`,
  делать скриншоты на разных стадиях морфинга, смотреть FPS и консоль. Итоговую оценку всё равно
  даёт автор на Mac и iPhone.
- Для кадров конкретного момента морфинга: `?manual`, затем в консоли
  `DP.morphTo('peony'); DP.debug.step(4)` — кадр на 4-й секунде (время стоит, пока не вызван step).
- FPS-счётчик на сайте: параметр `?debug` (FPS, WebGL1/2, качество, pixelRatio, число точек).

## 3. «Запомни» / «сохрани» / «сделай дубликат»

1. Скопировать текущую версию сайта в `versions/ГГГГ-ММ-ДД_ЧЧ-ММ_короткое-описание/`
   (всё, что нужно для работы: `index.html`, `css/`, `js/`, `vendor/`). Все пути внутри
   копии относительные, чтобы она открывалась по своей ссылке:
   `https://fuzzyfoxxyfoxx.github.io/Dark-Peony/versions/<папка>/`
2. Поставить git-тег с тем же именем (`git tag <папка> && git push origin <папка>`).
3. Добавить запись в `versions/README.md`.
4. Прислать автору ссылку на эту версию.

## 4. Список версий

`versions/README.md`: дата, ссылка и что в этой версии понравилось.

## 5. Время

Время в названиях версий и тегов — по Амстердаму (`TZ=Europe/Amsterdam date +%Y-%m-%d_%H-%M`), не UTC.

## 6. Возврат к сохранённой версии

Восстанавливать `main` из соответствующего тега: содержимое рабочих файлов берётся из тега
(`git checkout <тег> -- .` без удаления папки `versions/` и её README), затем обычный коммит
«Restore <тег>» и пуш в `main`. Историю `main` не переписывать (без force-push).

## Текущее состояние (для новой сессии)

- Пион перенесён из `archive/Gedal_web_preview_005_crossplatform.html` один в один — вид утверждён автором.
- Морфинг пион → пион (кнопка MORPH / пробел). Утверждено автором: распад и сборка идут
  от краёв к центру и низу (`assemble: 'outside-in'`), 360° (было 720°, автор попросил попробовать 360°), уход и посадка перекрываются.
- Отклонено автором: воронка/конус; уменьшение частиц в полёте (давало эффект «кометы наоборот»,
  сейчас `swirlSizeMin: 1`); равномерный «туман» в середине — частицы не видны, если не скучиваются.
- В работе: середина морфинга. Цель по референсам автора (Trapcode Particular в After Effects):
  плотные светящиеся жгуты, перепонки и ленты частиц, которые скручиваются в кольцо вокруг оси,
  плюс пыль вокруг. Сейчас: кольцо размером с цветок, сечение-«крыло» (`ring*`), частицы стянуты
  в тонкие жгуты (два шага Ньютона, поля в реальной позиции частицы), поля живут в потоке
  (`fieldSpin`, `fieldShear`, `clumpSpeed`). Волокна по уровням шума (`clumpFibers`) пробовали —
  давали муть, выключены. 360° вместо 720°; цветок непрерывно переходит в кольцо (не «наплывом»);
  лидеры с хвостами (`trail*`) дают штрихи вдоль потока. Цвет референса (золото) не интересует —
  только фактура.
  Автор: «частицы идут по ровным кругам» — добавлены перекрут ленты (`twist*`) и сильный двухволновой
  поток; «дальние лепестки вспыхивают при отрыве, как наплыв» — яркость вихря набирается поздно
  (`swirlBlend`), подсветка отрыва ослаблена (`leaveGlow`).
  Автор: «хаос, как УЗИ» → новый референс — распад человека в частицы: тонкие волнистые нити.
  Сделаны нити (`threadCell`): частицы ячейки сечения идут по одной линии. Стягивание, перекрут
  и хвосты выключены (давали хаос). Не решено: в момент срыва частицы идут дымкой, а не нитями,
  растущими из поверхности.
  Автор: «нити — треш, частицы щупалец не сводить в кольцо, пусть остаются на своём уровне и идут по
  синусоидам сильных полей»; референсы — видео распада черепа: поверхность срывается цельными вуалями.
  Сделано: `ringMode: false`, поле от исходной точки (слои цельные), нити выключены.
  Проверять плотным контактным листом: 16 кадров через 0.5 с на одном снимке (автор просит плотную
  раскадровку — по редким кадрам ошибки движения не видны). Кадр WebGL копируется в 2D-canvas сразу
  после `DP.debug.step()`.
  Найден и исправлен баг: оставшийся `twistSpeed` крутил сечение со временем → цветок схлопывался
  к центру (щупальца ныряли в центр), потом разлетался. Сейчас: частицы стекают, облетают Y на своих
  уровнях, поле умеренное (`flowAmp 0.3`) — вуали со складками, цветок не меняет размер.
  Щупальца — эталон автора: распадаются на частицы и собираются из потоков частиц. Этот распад даёт
  случайный разброс времени у каждой частицы (ORDER_JITTER, travelJitter) — его НЕ убирать
  (пробовали — распад пропал, автору не понравилось). «Дребезжание» при разборе давали только дрожь
  перед отрывом (`shiver`) и вспышка (`leaveGlow`) — они выключены (0).
  Поле нарастает вместе с поворотом, а не сразу (`fieldDelay`, `poseBlend`): сначала частица плавно
  уходит по кругу, потом среда её разбалтывает; при посадке поле гаснет раньше конца поворота.
  Поле течения переделано (вариант «A», без GPGPU): среда толкает, а не сдвигает — смещение = сумма
  толчков поля водоворотов (∇n1×∇n2) вдоль пройденного пути за `flowMemory` с (`flowSteps` отсчётов,
  по качеству 5/4/3); поле вращается с вихрем медленнее частиц (`fieldSpin`) и меняется во времени.
  Автор: флуктуации поля среды выглядят инородно → поле выключено (`flowAmp: 0`, код оставлен).
  Вместо него — «морская волна» (`wave*`): радиус не меняется, частица качается только по вертикали;
  фаза от места и времени (не случайная), поэтому соседи качаются вместе, без хаоса.
  Темп (по просьбе автора): уход ×1.4, вихрь ×5, посадка ×2 (`speedIn/speedMid/speedOut`),
  участки пути сшиты плавно; весь морфинг ≈ 8.3 с (было 12.7). Разбор и сборку по времени не трогать.
  Автор: волна и ускорение — «всё плохо», попросил попробовать реалистичный вариант B (GPGPU) и оценить
  нагрузку. Сделано: `js/core/flowsim.js` — симуляция среды на видеокарте (одна текстура отклонений,
  один проход в кадр). Замер на MacBook M3 Max: морфинг 67 FPS с симуляцией против 74 без неё
  (≈10% кадров); WebGL1 работает. iPhone не проверен — это решающая проверка.
  iPhone 15: симуляция не проседает (проверил автор). Внешний вид «не отличается от прежнего» →
  поле сделано попутным (`fieldSpin: 1` = средняя скорость вихря), сильнее (`flowAmp 1`, `flowFreq 0.5`,
  `simSpring 0.2`); введена «сплочённость» (`simCohesion`): у концов пути частица идёт по своему
  расписанию (распад/сборка по частицам, `orderJitter`, `travelJitter`), в вихре догоняет общий поток —
  полотна не размываются в туман, и водовороты рвут/скручивают их целиком.
  Автор против тяжёлых решений: сайт должен работать на разных устройствах. Если «A» не хватит —
  обсуждать с автором (возможно, другой принцип: волна, пробегающая по фигуре), GPGPU не начинать без согласия.
  Отложенный шаг: лепестки распадаются «нитями» как щупальца — полоски вдоль
  лепестка со своим сдвигом времени, внутри полоски частицы уходят строго по очереди (лидер и хвост).
  Если этого мало — следующий шаг: частицы, которые помнят траекторию (шлейфы/streaks, GPGPU).
- Медуза готова (`js/figures/jellyfish.js`, эскизы автора): купол «вдавленная сфера» с каналами и
